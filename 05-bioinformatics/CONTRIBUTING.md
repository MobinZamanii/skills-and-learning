# Contributing

Contributions that improve scientific accuracy, reproducibility, clarity, accessibility, or code quality are welcome.

## Before opening a pull request

1. Explain the scientific or educational issue being addressed.
2. Keep examples reproducible and use public data with documented terms.
3. Cite primary sources, software versions, and dataset accessions.
4. Avoid committing large, restricted, or personally identifiable datasets.
5. Run the notebook from a clean kernel and verify outputs.
6. Explain assumptions, limitations, and expected computational resources.
7. Keep code readable and comments in English.

## Notebook conventions

- Use descriptive Markdown headings.
- Explain code before running it.
- Avoid hidden state and out-of-order cell dependencies.
- Set random seeds when appropriate.
- Do not include credentials, local absolute paths, or private data.
- Prefer small example datasets for teaching; document how to obtain full datasets.
